# 命令行位置参数诊断补充（2026-10-29）

用户反馈包含 `-tune:v:0 animation`、`-map_metadata 0`、带空格与全角感叹号路径的命令报 `One output filename must be the last argument`。

在当前程序中，将所给参数按独立命令行参数传入可正常解析。对用户指定的实际文件运行只读 `--analyze` 成功：23 秒至 75 秒，共 52 秒、3120 帧；计划复制 2993 帧、编码 127 帧，视频参数为 libx265 / slow / animation / CRF 24。本轮没有执行完整素材导出，不将计划成功视为实际导出验收。

在程序名后额外传入 `ffmpeg.exe`，例如 `smartcut.exe ffmpeg.exe -i ...`，可以复现原有通用错误；把未加引号的输出路径拆为多个参数也会触发同一错误。这证明是可复现的触发方式，尚不能确认用户现场实际收到的参数正是其中一种。

修改 `src/cli.cpp` 的诊断：显示异常参数的序号、内容、相邻参数，分别提示多余命令名和带空格路径的引号。没有自动删除参数，也没有改变有效命令的解析规则。`tests/unit.cpp` 加入原始完整参数向量、Unicode 路径、MM:SS、tune、metadata，以及上述两类错误的检查。

MSVC Release 构建通过；更新后的 CTest 2/2 通过；实际命令只读分析、额外命令名、拆分输出路径三项进程级验证 3/3 通过，见 [结果](evidence/cli-arguments-20261029.json)。此前 551 项报告保留为上一轮构建的独立历史记录，本补充不声称对新构建重新执行了整个视频矩阵。
